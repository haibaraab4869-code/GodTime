# 发布与运营管理

本目录存放发布准备、版本记录、补丁说明和回滚材料。**当前仅为规范模板，不代表已经确定目标平台、配置导出预设、完成构建或发布。** 立项案已指定目标平台为 Steam，但尚未据此建立任何渠道与导出配置。已核实：项目存在可启动的 2D 探索原型（`game/main.tscn`，Godot `4.7.2`），但**未发现 `export_presets.cfg`、构建产物或 Git 仓库**，故不能据此判定游戏可发布。首发范围、渠道细节、语言、商店页及上线日期均待项目负责人批准。

## 版本与发布记录

- 首次对外版本号、命名方式和发布渠道由负责人确认；确认后建议使用 `主版本.次版本.修订号`，修订号用于兼容性修复，所有商店展示版本、游戏内版本、构建标识与发布记录须一致。
- 每次候选发布记录：版本号、目标平台/渠道、构建时间、源码修订标识（如有）、Godot 精确版本、导出预设与配置、内容/语言包版本、产物文件名及 SHA-256、负责人和审批结论。未建立版本控制前，不得虚填修订标识；建议先建立可追溯的源码基线。
- 候选包与最终包分开存档，不覆盖已批准的上一个稳定包；每个平台单独记构建与验收结论。

## 发布前跨部门清单（逐平台勾选）

- [ ] **范围/平台**：负责人书面确认目标平台、渠道、地区、语言、日期和本次内容边界。
- [ ] **代码/构建**：开发负责人确认源码基线、依赖与引擎版本；配置目标平台导出预设，使用锁定配置生成可重现产物，核对版本与 SHA-256。
- [ ] **质量**：测试负责人在目标设备/环境执行安装、启动、核心流程、存读档（若适用）、性能及崩溃检查；阻断问题清零，非阻断问题记录影响与处置。没有实测记录视为未通过。
- [ ] **内容/本地化**：确认所有提交资产授权；目标语言的文本、字体、UI 截断、字幕/语音（若适用）在目标平台验收；冻结字符串并记录未覆盖项，未选语言不填覆盖率。
- [ ] **商店/法务**：按实际渠道核对商店文案、截图/视频、分级、隐私政策、许可、付费与区域合规要求；未选渠道时保持待定。
- [ ] **运营/社区**：准备玩家可读的更新说明、已知问题、支持与反馈入口、发布时间和异常沟通联系人。
- [ ] **恢复**：保存上一个稳定包与配置，演练实际渠道允许的回滚/下架路径及存档兼容；若无上一版，明确首发只能暂停或撤回。
- [ ] **签字**：开发、测试、内容/本地化、发行/运营和项目负责人分别确认；项目负责人最终作 Go/No-Go 人工审批。

**门控规则**：任一阻断缺陷、缺失构建/实测证据、未获必要平台或法务批准、无法执行恢复预案，均为 **No-Go**；仅项目负责人可明确书面豁免非阻断项，写明风险、期限和责任人。自动化检查不能替代人工放行。

## 平台发布流程

确认平台与渠道 → 为该平台配置导出预设和签名/凭证（仅安全存储，不入库）→ 构建并计算校验值 → 在目标环境验收 → 填完上述清单与签字 → 由获授权人员执行渠道上传/上架 → 验证可下载版本与关键指标。不同平台的打包、审核、分发、灰度和回滚能力需分别验证，不预设任何渠道能力。**不得仅因本目录存在就执行上线。**

## 更新日志与补丁说明

每次发布保留内部变更日志：版本与平台、源码/构建标识、发布日期、功能/内容变更、修复、兼容或存档影响、已知问题、风险及关联测试结果；内容以已合入变更和测试证据为准，不从设想推导。玩家补丁说明使用易懂语言，说明“有什么变化、需要玩家做什么、还有什么已知问题”，不包含未公开内部信息。未实际发布的版本标为“草稿”，不得写成已上线。

## 热修、异常与回滚

监测崩溃、启动失败、存档损坏、支付或服务异常（仅在相关功能存在时）；达到预先约定阈值或出现严重影响时暂停扩量并通知负责人。热修可缩短测试范围，但仍须留下变更、构建、目标平台验证、审批和回滚记录。回滚由负责人批准并由获授权人员执行：停止继续分发 → 确认受影响版本与用户范围 → 使用已校验的稳定包/渠道撤回机制 → 检查存档与数据兼容 → 复测并对玩家说明。若没有稳定包、渠道不支持回退或存档不可逆，先暂停发布并制定前向修复方案，不承诺可直接回滚。
