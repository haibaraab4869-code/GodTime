## 文档维护规则

1. **强制归档**：项目设计文档（包括地图、剧情、关卡和导出的 Word 文件）必须直接保存在 `docs/design/` 或其主题子目录；地图统一归 `docs/design/maps/`。用户已删除 `outputs/`，不得重建或将其作为中转目录；项目产物一律直接写入其所属的最终规范路径，不经临时文件夹周转。新文档先选上表中**一个**主分类并登记入口；勿创建同义目录或复制一份并行维护。跨领域内容用相对链接引用权威文档。
2. 文件名使用小写英文 `kebab-case.md`，标题和正文可用中文；同一主题只保留一份权威文档。涉及同一决策的变更修改原文，重要历史保留在版本记录，不新建 `-final`、`-v2` 副本。
3. 章节涉及未核实内容，明确标注“待定/待验证”，写明决策问题及验收条件；引用设定案时区分原案描述、团队决定和当前实现状态。
4. 文档变更随相应代码、资产或流程变更一起评审；链接尽量采用相对路径。删除或改名时同步更新本索引和所有引用。
5. **默认不备份、不复制**：未经用户明确要求，不得为项目文档创建 `.bak`、`-v2`、日期版、备份目录或在 `outputs/` 留交付副本；修改同一主题的权威文件。既有备份也不得未经用户逐项确认而删除。
6. 任何新目录、新常设文档、跨分类迁移，先检查本索引并搜索现有主题，避免重复建设。
