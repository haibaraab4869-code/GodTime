# 音频设计与实现入口

本目录记录《时间之神》的音乐、音效与语音方向及其实现需求。位于 `docs/design/` 的[《时间之神：类银河恶魔城游戏策划案（设定版）》](../design/时间之神：类银河恶魔城游戏策划案（设定版）.docx)是游戏立项设计案，仅作为既有设定参考；音频需求须在玩法交互、叙事和目标平台明确后逐项确认。当前项目尚无已核实的音频素材或音频事件实现，以下为待补充的文档框架，不代表已完成设计。

## 文档与资源的边界

- `docs/audio/`：方向、事件规格、混音及验收要求等**文档**；不存放音乐或录音成品。
- 未来实际音频资源及其导入配置应在项目资源目录中集中管理；具体目录和命名规则待与工程负责人核定，不能将本目录当作运行时资源路径。
- 设计描述、已批准规格、已交付资源、已接入引擎与已验收效果是不同状态，事件记录应分别标注，不以“计划制作”冒充“已经接入”。

## 事件文档的最小字段

后续建立音频事件表时，每条事件至少保留：**事件 ID（命名规则待定）｜交互/场景来源｜触发条件｜停止或过渡条件｜功能和情绪目的｜优先级｜变体与分层｜2D/3D 和衰减需求｜目标总线｜资源及授权状态｜实现状态｜验收方法｜责任人/待决问题**。只有在交互定义明确后才列具体事件；不预设事件数量、参数或素材。

## 决策与验收前置条件

1. 策划确认核心交互、场景状态与叙事节奏；美术确认视觉情绪，音频方向据此给出选项并交用户拍板。
2. 工程确认 Godot 4.7 项目实际使用的音频方案、目标平台及导入/运行约束；中间件是否使用仍待决，不假定已采用。
3. 音频与工程共同验证格式、音量和性能指标，确定事件命名及资源目录；每项指标注明验证设备和方法后再固化。
4. 所有外部或生成素材均记录来源、许可范围、授权证明及署名要求，未完成审核不得视为可发布资产。
5. 每项资源以听感、交互触发、混音可辨识度、循环/过渡、平台表现与授权齐备情况验收，并同步更新事件状态。
