## 实施范围

- `game/main.tscn` 保留作为项目入口，根节点改为 `M01NamelessFerry`；旧demo的地形、木桩实例及测试终点直接替换，无并行测试地图。
- `game/m01_layout.gd` 独占地形、入口和交互坐标；`world.gd` 负责M01交互与进度；`paper_warden.gd` 提供可绕过的纸人遭遇；`m01_journal.gd` 提供暂停阅读。
- M01葬帖、两态船夫证词、壁画两层、旧闸锁存、船工刻痕、望台和纸人击败状态独立保存。保存路径 `user://m01_progress.cfg`，格式版本1。载入回入口，生命、时代与当前位置不作为跨进程存档。
- E／RB调查，Q／LB日志，Tab／Y切时，Esc／Start设置；均使用动作层，调查与日志可改键。读取界面可以用交互键、日志键、Esc或按钮退出。
- M02／M03只提供明确的地图接口与 `exit_requested(map_id, anchor)` 信号，不加载尚未制作的地图。原有高级能力和四凶独立模块没有在本次挂入玩家。

## 自动验证

运行方式：`Godot --headless --path . --fixed-fps 60 --script res://tests/<脚本>.gd`。以下七份脚本最终均退出0且 `FAILURES=0`：

- `test_m01.gd`：59项检查，包含真实物理移动、普通跳跃和语义事件注入，并隔离M01用户存档。
- `test_attack.gd`：基础命中、朝向、单次伤害、冷却与木桩行为；三个木桩改由测试动态创建，不回塞进剧情地图。
- `test_visual.gd`：骨骼模型、动画、对齐、翻转及片段切换。
- `test_input.gd`：九个动作、双设备改键及持久化；本轮将测试配置改为独立 `user://test_input_bindings.cfg`，避免清除玩家的实际改键。
- `test_input_feel.gd`：现有输入缓冲与攻击冷却检查。
- `test_abilities.gd`、`test_combat.gd`：现存独立模块的规则回归；它们通过不代表这些系统已接入M01。

M01核心路线不是只检查坐标常量：测试让真实Player从泊位走到桥端，切时后下到桥洞，领取葬帖、从封闭桥洞切回，再用原始单跳完成返岸。上层沿过去桥与水轮廊抵达M02接口；下层穿过已开的旧闸抵达M03接口，最后沿石阶跳回旧闸上岸。中间石阶实际中心y约531.995、返岸y约459.925，无二段跳、空冲或穷奇位移。

另外验证：阅读暂停后仍能用语义输入关闭；封闭但能站立的桥洞不扣血；可选高台切入实体只扣1血并安置到有支撑、可横移的安全点；生命为1时回共同检查点；超出附近搜索范围回检查点；624px低层可参与安全复位；壁画及纸人不锁出口；攻击预警、闪避与单次伤害；新场景从ConfigFile读回葬帖和两态闸锁。主动起跳不再重新发放土狼时间，空中冲刺输入不再被提前消费，也不因此获得空冲权限。

## 限制与后续验收

- 当前为程序化灰盒，无正式场景贴图、环境音频、配音或魂魄经济；壁画提供可选证词，未虚报魂魄到账。
- M01的安全落差180px、复位搜索半径480px、返岸72px级差仍是灰盒参数，需要新手试玩。未完成地图知晓度、手感、最小配置或真实手柄硬件验收。
- `tests/test_player_integration.gd` 是此前已有的未来战斗集成脚本，依赖当前Player不存在的 `combat` 等接口及已移除的木桩节点。本轮未执行／未记通过；后续接入完整四凶控制器时应重写其场景夹具，不能通过恢复旧demo来迎合它。
- 局部进度不等于完整存档：缺少多槽、迁移、损坏恢复与原子写入；本轮验证的是新场景从同一磁盘配置重载，未据此声称全系统跨进程保存已验收。
- 首轮暴露了悬空薄踏板从下方起跳会顶头的问题，已改为实体踏石，并在真实单跳往返测试中复核。没有以提高跳跃速度、临时给二段跳或测试传送越过该障碍。

下一步：新玩家从无进度状态试玩，观察能否发现桥端切时、理解桥洞入口与返程、区分可选切墙练习和主路、找到两条出口。M01问题收敛后再实现M02。
