## 0. 为什么需要这份文件

29 区替换 48 区之后，9 个探索能力在运行时**没有任何取得入口**：

- `game/data/world_regions.json` 的 29 个 region，`ability` 字段全为空字符串，`interactions` 里只有 `travel/item/device/rest/boss`，**没有 `world_ability`**；
- `tools/build_runtime_world.py` 第 396 行写死 `"ability": ""`；
- `docs/design/maps/data/wXX.json` 顶层原本没有 ability / grants 字段，能力只写在单图 MD 的正文里；
- 后果：36 条边里 18 条带 `requires`，主线 E08（W06→W08）需要 `P2`，玩家在第二章就卡死。

因此本文件把散落在 8 份单图正文里的取得点**规格化成结构化数据**（`grants` 段），并补齐两条原文未给坐标的条目（`DT` / `DB`，坐标依据见 §4）。

**不变的硬约束（本表每一条都已逐条复核）**

1. **取得前可进可出**：任何取得室在玩家还未持有该能力时，都必须有进得来、也出得去的通路，不得出现「进了房间出不去、只能靠刚拿到的新能力离开」的自举死锁（逐条复核见 §3 各条的「取得前可进可出」段，`PW` 的边界说明在 §3.5）。
2. **门只在取得点之后**：不存在「必须先通过某门才能取得该门所需能力」的循环（总控 §5 第 196 行的硬约束）。
3. **不改几何**：本文件**未改动任何 `rooms[].rect` / `size` / `canvas_origin`**。29 区是精确铺满的，改一个 `rect` 就破铺满、破共边门位。
4. **坐标是区局部画布坐标**：与 `items[].pos`、`interactions[].at`、`checkpoint.pos`、`world_links[].pos` 同一坐标系；世界坐标 = `canvas_origin + pos`，只作参考列。

## 3. 逐条说明

每条固定六段：取得物与判定几何 / 取得前可进可出复核 / 取得后首个验证 / 失败反馈 / 是否门禁 / 坐标复核。文案见 `data/wXX.json` 的 `grants[].text`。

### 3.1 `VC` 时间切换 · W01 R03 桥心 (1670, 544) · both

- **取得物与判定几何**：刻漏阁西面（x 1660—1696）的漏箭。玩家站上桥面即可交互，切时判定点唯一：x=1670（阁体西侧 26px），要求角色矩形（24×40）在目标时代不重叠任何实体。现在态该处 y 576—960 全空 → 合法切换。
- **取得前可进可出复核**：**通过**。R03 取得前有两条通路：西 W→R02 桥西台、北 N→R05 桥楼（过去态）；东 E→R04 需切时才成立，但**不是唯一出口**。取得过程中不锁门、不位移，玩家不会被关在房间内。
- **取得后首个验证**：同房间切时坠落 384 → 960 河床（教「切到没地的一侧会掉，但只掉位置不掉血」）；紧接着 R03→R04 跨 272px 断层（教「缺口只能靠换边解」）。
- **失败反馈**：见 §2。全作**第一次**出现「当前位置无法使用该能力」，出现在玩家已经学会切时之后，不打断教学。
- **是否门禁**：是。且它是全作地基，**不设回环**（总控 §5 第 366 行「不可能跳过」）。
- **坐标复核**：R03 rect (1280,320,832,640)，floor_y 576；判定点距地面 **32px**（站姿身体区间 536—576，落在胸口）；四边余量 左 390 / 右 442 / 上 224 / 下 416，均 ≫ 20px。与 I-03 刻漏残铭 (1500,544) 相距 170px，可区分。
- **文案**（`grants[0].text`）：「漏箭停在旧刻上。按下它，脚下的城便换回没塌的那一半。」

### 3.2 `P2` 凤凰二段跳 · W06 R13 巢心 (960, 500) · past

- **取得物与判定几何**：过去态巢口（y=480）悬挂的「燧羽穗」。判定点 y=500 悬在巢口下方 20px，玩家站在高台（y=520）时正对身体区间（480—520），无需跳跃。

- **是否门禁**：是。R13 东侧唯一门洞在 y 448—536，从房内最高可站点（断梁残端 760）上去需 **224px** → 单跳不可、`P2` 可；同房间即完成首次必需使用，失败无跑图成本。
- **坐标复核**：R13 rect (480,448,960,512)，floor_y 960；四边余量 左 480 / 右 480 / 上 52 / 下 460。x=960 为房宽正中，与 I-09 魂魄 (700,500) 相距 260px。

## 4. `DT` 与 `DB` 的坐标决策（原文未给坐标）

两处的原文档都只说「触碰龙尾骨」与「三口泉眼」，没有给数。本文按「房间内可达性 + 不误触相邻交互 + 留碰撞体余量」三条定坐标。**未改动任何 `rect`。**

### 4.1 `DT` = R01 (1020, 752)

房间 R01 龙尾葬台 rect (880,0,880,800)，`floor_y = 800`（拱顶，过去态空旷、现在态蜡骨封壁）。定点的三条约束：

1. **不能落在东墙破壁位**：R01 东墙 x=1760 是 `DT` 取得后当场要破的薄骨墙（480×320）。判定点距东墙 **740px**，取得瞬间不会误触破壁、也不会让玩家在读「取得」与「破壁」两个反馈时混为一谈。
2. **不能落在地板脆板上**：原文「R01 地板中央有一块颜色略浅的脆板」（判定几何 480×160），居中即 x 1080—1560 一段。判定点 x=**1020**，在该段西侧外 60px——玩家站在脆板上取能力时不会一并触发地板破坏。
3. **要贴着「不可破对照」的西墙，且必须站得住**：西墙 x=880 是普通石面（只有骨纹、无划痕、无蜡光），是教学三件里的对照组。龙尾骨斜卧在葬台西侧、贴西墙内侧面，判定点距西墙 **140px**（≫ 20px 半宽余量），玩家不走进墙里也能触碰。
4. **高度取站姿胸口**：y=**752** = 地面 800 − 48。角色矩形 24×40，站在 800 地面上时身体区间是 760—800，判定半径 48 覆盖 752，无需跳跃、无需冲刺。
5. **与 I-01 刻辞区分**：I-01 龙尾葬台刻辞在 (1320,760)，相距 **300px**，两个交互不会同时进半径。
6. **与 R03 入口的关系**：唯一进出是 W→R03（x=880 侧），判定点在房内偏西、离入口 140px，玩家一进房就在视线内，但不会在跨区落点位置被自动触发（落点在房西侧贴墙 48px 处，距判定点 92px > 48 半径）。

### 4.2 `DB` = R09 (2304, 5064)

房间 R09 龙息双泉 rect (1536,4096,1536,1024)，`floor_y = 5120`（拱顶，全区最低处）。定点的四条约束：

1. **必须是中泉，不能是冻泉或蚀泉**：三口泉眼中，冻泉与蚀泉各自是玩家要主动操作的 `DB` 目标（冻水 / 酸蚀），若把取得点放在其中之一，取得动作会与已有操作目标抢同一套输入，且「取得」会被误读为「第一次操作」。**中泉自身不是任何操作目标**，是唯一干净的取得位。
2. **水平居中，两侧等距 384px**：x=**2304** 正是房间宽度中点（1536 + 1536/2）。冻泉定在 (1920, 5064)、蚀泉定在 (2688, 5064)，取得点与两侧操作目标**对称等距**——玩家校准完三灵后不必挪位就能看见左右两侧各有一口可试的泉，方向感最省。
3. **高度取齐另外两处「台面高 56」的先例**：y=**5064** = 地面 5120 − 56，与 `DS` 鳞台高 56、`PG` 取得台 298 同族（低矮石台读法）。角色站姿身体区间 5080—5120，判定半径 56 覆盖 5064；玩家走到中泉前即可俯身接息，不需跳跃。
4. **在取得后必须能立刻看见两条自验证路**：中泉正对 E→R10（冻台试池，自验证①）与 N→R11（蚀壳试壁，自验证②）的方向，两口自验证房的门都在取得位的视线包络内（房高 1024，取得位距地 56，抬头即可见 R08 下来的泉阶与东口）。
5. **余量**：四边 左 768 / 右 768 / 上 968 / 下 56，全部 ≫ 20px；不在墙内、不悬空。

> `DB` 的 `w21_trinity_3`（`D2` 三灵协作第 3 档）**不在 `grants` 契约里**（契约只有 7 个键，见 `_schema.md` v1.4）。运行时须在发放 `DB` 前读 `devices[].flag` / `solution`：未满足时中泉只冒泡、不给能力。这是工程侧的接入点，已列在 §5 第 2 条。
