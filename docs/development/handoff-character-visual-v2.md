## 0. 一句话

v1 把袍身从「隐形黑块」提到了 3.80:1，但它**形状还是旧的**。本单按母版重画 16 个部件，把剪影 IoU 从 **0.581 提到 0.721**、近黑占比从 **35.7% 降到 15.2%**（母版 10.5%）。

参照实现已跑通：**`tools/_proto_parts.py`**（写临时目录，跑一次就出对比图）。**不要直接拿它当产物**——它的 `PIVOTS` 还是旧值，是故意留的，见 §4。

## 1. 先明确一件事：不是「换模型文件」

「把 AI 母版切成 16 个部件替换上去」**不可行**，原因有三条实测：

| # | 事实 | 后果 |
| --- | --- | --- |
| 1 | 母版下半身 **97.2% 是袍，只有 2.8%（46px）露脚** | `leg_thigh` / `leg_shin` 在母版里**没有像素**，切不出来 |
| 2 | 母版袍是**一整片连续伞形** | rig 的 `hem_front` / `hem_back` 是两片，切过来腰部必露缝 |
| 3 | 母版是单姿势，前臂压袍身、袍压腿 | 被遮挡区没有像素可补，一动就穿帮 |

所以只能**重画程序化部件**。这也是本单唯一的路，好处是部件边界天然干净、遮挡区天然完整。

## 3. T1 · 重画部件（必做）

参照 `tools/_proto_parts.py`，改 `tools/gen_parts.py`。改动清单：

### 3.1 全局：描边减细

加常量并在 `fill` / `ellipse` / `stroke` 里统一乘上去：

```python
# 母版近黑仅 10.5%，现状 35.7%。主因是描边太粗 + 头发团太大。
EDGE_K = 0.55   # 1.3 -> 0.72px @128，接近母版那种"几乎看不见的边"
```

三处 `width=max(1, int(round(ew * S)))` 全部改成 `ew * S * EDGE_K`。

### 3.2 `p_head` —— 缩后脑、**不动脸宽**

| 项 | 现状 | 改为 |
| --- | --- | --- |
| 后脑发团 `back` | x 44–66，y 9–47 | **x 52.4–66.2，y 9–36.8** |
| 面部 `face` 前后径 | 21px（x 62.8–83.6） | **17px（x 62.8–80.0）** |
| 刘海 `cap` 后缘 | 46 | **54** |
| 颈后发尾 `stroke(56,34)-(58,42.6)` | 存在 | **删除**（母版 y=40 只剩脖子） |
| 五官 | 眼/朱砂/嘴/鼻底 | 随 face 等比内移，见原型代码 |

### 3.3 `p_crown` —— 改五尖宽冠

## 4. T2 · 枢轴同步（**本单最容易做错的一步**）

部件形状改了，**枢轴必须跟着改**，否则旋转中心落在部件之外。但枢轴同时存在于三处，必须一起改：

| 位置 | 常量 | 现状 | 改为 |
| --- | --- | --- | --- |
| `tools/gen_parts.py` | `PIVOTS["torso"]` | `(64, HIP_Y=88)` | **`(64, 74)`** |
| 同上 | `SASH1` | `(58, 80)` | **`(58, 74)`** |
| 同上 | `SASH2` | `(54, 85)` | **`(54, 79)`** |
| 同上 | `HEM_PIVOT` | `(64, 84)` | 保持（新裙 70–107，84 在中上部，合适） |
| `tools/build_rig.gd` | 对应骨骼 rest 坐标 | — | 与上表同步 |
| `assets/characters/shihung/rig/shihung_rig.tscn` | `Bone2D` 的 `position` | — | 与上表同步 |

> **为什么这条必须写死**：`poses.json` 是 Godot 导出的骨骼**当前**位置，而渲染时部件绕 `PIVOTS` 里的**静止**枢轴旋转。只改一边，`rest` 和 `cur` 就对不上，姿态表里躯干会整块甩出去——我在这上面栽过一次，误以为是动画坏了。
>
> **正确顺序**：改 `gen_parts.py` 的 PIVOTS → 改 `build_rig.gd` → 重建 rig → 重导出 `poses.json` → 再跑 `render_pose_sheet.py` 验收。**四步缺一不可。**

`torso` 枢轴从 88 提到 74 后，`run` 的 10° 前倾位移从 2.4px 降到 0（旋转中心落在躯干内）。

## 5. T3 · 验收

**Given** 深蓝天空 `#142032`、`RIG_SCALE 0.5`（约 58px 高）
**When** 截图算 WCAG 对比度与剪影 IoU

1. 袍身对天空 **≥ 3.0**（预期 3.80，v1 已达标，本单不得回退）
2. 近侧袖 ≥ 4.0（预期 4.66）；金饰 ≥ 6.0（预期 6.49）
3. **剪影 IoU vs `master_128.png` ≥ 0.70**（现状 0.581，原型 0.721）
4. 近黑像素（灰度 ≤60）占比 **≤ 18%**（现状 35.7%，原型 15.2%，母版 10.5%）
5. 58px 下冠、脸、交领金线、下摆金边仍可辨
6. `run` / `dash` / `attack` 三个 clip 逐帧无部件飞散、无躯干与裙分离
7. 循环闭合：`t=0` 与 `t=循环终点` 所有轨道值相同

**度量脚本**（设计侧已备好，直接跑）：
- `tools/_proto_compare.py`：三列并排 + IoU + 近黑占比 + 袍身 CR
- `tools/_iou_decompose.py`：平移搜索拆位置/形状误差 + 逐行宽度剖面（定位差距用）
- `tools/_proto_poses.py`：用 `poses.json` 渲染原型部件的姿态表（查穿模）

## 6. 代价声明（必须让策划知情）

**这一改，跑动时看不见腿了。** 新裙到 y=107、脚在 112–120，小腿以下露出、大腿全遮。

- 好消息：`leg_*` 四条骨**完全不用动**，脚仍随腿骨摆动，58px 下能读出「在动」
- 代价：`thigh` 的 ±26° 摆腿看不见，步态节奏靠**脚部运动 + 身体起伏 + 裙摆轻微跟动**表达
- 这与用户 2026-10-29 定的 `breath` 档（布料不晃、只呼吸）一致，不冲突

如果以后要恢复可见步态，只有两条路：把裙收短到膝上（回到 v1 造型），或改 `rig` 为前后两片裙（会重新引入腰部缝）。

## 7. 不要做的事

| # | 禁止 | 原因 |
| --- | --- | --- |
| 1 | 把 `face` 前后径缩到 14px 以下 | 五官会糊成一团，58px 下读不出脸。17px 是实测下限 |
| 2 | 只改 `gen_parts.py` 的 PIVOTS，不同步 `build_rig.gd` | `rest` 与 `cur` 错位，躯干会整块甩出去 |
| 3 | 删掉 `hem_back` 骨骼 | 11 个 clip 里有轨道引用它，删了会断链。**留骨、留空部件**即可 |
| 4 | 把袍身色改回 `#221F1C` 或调回 v1 之前的墨阶 | 已两次实测 1.00–1.14:1 |
| 5 | 用「统一乘系数」缩放部件曲线 | 头、裙、袖的物理角色不同，v1 的教训（spec §12.9.1 经验 2） |
| 6 | 动四条腿骨、四条臂骨的角度 | 它们是 rig 相对序列帧的价值所在 |
| 7 | 改 `player.gd` 的 clip 名或 `CLIP_PRIORITY` | 三方对齐，改名连带断链 |
