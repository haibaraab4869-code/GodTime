请执行《时间之神》第 01 章竖向重排的推广施工（M02–M06）。M01 已完成，不要重做。

先按顺序读这四个文件：

2. `docs/design/maps/时间之神_第01章_竖向重排表.md` —— 同一份数据的可读版，对照用。
3. `docs/design/level-flow-chapter-one.md` —— 探索流程设计：七拍结构、平台有效性判据（5 条禁止）、深度提示分工、验收条款。
4. `docs/design/feature-map-reconstruction.md` —— v3.1 上位规格（固定镜头 zoom 1.6、D1–D5 定义）。与前三个冲突时以它为准。

## 这次要做什么

把 M02–M06 的房间地面高度改成 JSON 里写死的值，让竖向落差从「全部 512」变成设计过的 3–5 种深度，然后按配额生成平台。

具体四步：

1. **改房间底边 y**：每个区按 `groups[].bottom` 移动整组房间。同组房间必须保持同一底边（组内是横向走廊，改错会断墙）。
2. **按几何重推 tier**：不要读 `structure.connections[].tier` 里的旧标签——M01 的标签就和几何不符（落差 224 标 D1、448 标 D4）。一律用 `落差 → BANDS` 重新算，再按等级给 `landings` 配额（D1=0 / D2=1 / D3=0 / D4=1 / D5=2）。
3. **删掉 M02 的 VC 发放**：`M02.ability = "VC"`，但观照机制已在 v3 作废。这个发放点必须删除，否则玩家会拿到一个不存在的能力。
4. **深度提示落地**：JSON 里 `cue` 字段指定了每处 D4/D5 用垂索还是回声；M03 的 768 井要四重全上（井口宽 64–80 + 垂索贯穿 + 两块落脚分居首屏次屏 + 回声）。

## 验收（做完自查，我不会替你验）

- 每区实际竖向落差集合 == JSON 的 `distinct_drops`，逐条对上，不允许近似
- 浮台数 ≤ JSON 的 `platform_budget`（M02=3 / M03=8 / M04=4 / M05=5 / M06=7）
- 落差 ≤450 的连接上浮台数 == 0
- 落差 ≥451 的井，首屏内能看见第一块落脚
- 全区 `camera.zoom` 恒为 1.6，无任何缩放分支
- 第 01 章无强制下劈（pogo_gates 全为 0）

## 建议节奏

先只做 **M02**，跑通并截图，我确认后再做 M03–M06。M02 只有 4 层 10 房间，是改动最小、又能验证全套规则的一区。

## 三条红线

1. 不要重新引入任何缩放/取景——已明确取消，不要再加 `view_wide` / `view_close` 之类分支
2. 不要改下劈闭合逻辑（`pogo()` 只在 PA/P2 解锁时刷新），改了会破坏后期能力门
3. 不要改地刺伤害数值（已定固定 1 点 + 复位到最近安全落脚点）

## 回传清单

1. 改动文件清单
2. 每区实际浮台数（改前 / 改后），改前基线：M02=65 / M03=64 / M04=49 / M05=49 / M06=62
3. 每区实际落差集合（与 JSON 逐条比对的结果）
4. 自动化断言结果 + 回归测试结果
5. M02 实机截图（井口一张、井中一张）

## 拿不准的时候

规格或数据没写到的，按最保守方案实现，并在验证记录里标「待确认」，**不要自行扩展机制**。如果认为规格本身有矛盾，指出具体章节，我回来改规格——不要用代码绕过它。
