## 1. 十二条红线（违反任何一条，后面全要返工）

1. **不手改设计 JSON 的坐标**。要动拓扑就改 `tools/build_world_coords.py` 的 `CHAIN` / `BRANCH` 再重跑，它会重算 29 份 JSON 的 `canvas_origin` 与 `world_links`。
2. **`rooms[0]` 就是出生房**。`world_data.spawn()` 取 `rooms[0].rect` 算出生点 `(x+48, end.y-20)`，所以每区 **R01 必须是入口房**，且它的 `floor_y` 必须在底部，否则玩家一进场就悬空。
3. **`structure.connections` 必须与 `links` 逐条对齐，且 `link` 字段等于该 link 的索引**。`map_slice_geometry.build()` 对竖直连接会做 `data.structure.connections.filter(link==i)[0]`——**缺一条就下标越界崩溃**，多一条不会报错但会错位。
4. **`bounds` 必须写成 `[0, 0, size.x, size.y]`**。`build()` 用 `area.end` 当宽高、**完全忽略 `area.position`**；写成世界坐标会把墙体栅格化到区外。
5. **所有房间 rect / 门位 / 交互坐标都是区局部坐标**。`world_origin` 只给大地图（`world_atlas.gd`）与镜头用。
6. **`mythic` 键必须存在**（`world_data.geometry()` 无条件调 `region(id).mythic.has(...)`），但**不要塞假的 `steps`**——按 §4.6 加两行护栏，让没有 mythic 的区安全跳过。
7. **每条边两侧各要一条 `travel_<对端区号>` 交互**，`edge` 字段写同一个 edge id，`side` 决定进场偏移方向（-1 = 从左侧进，+1 = 从右侧进）。`world_atlas` 也靠 `travel_<id>` 命名取锚点。
8. **灯龛交互的 id 必须是字符串 `"rest"`**（`chapter_one.gd:225/244/384/552` 硬判定），不能写 `rest_W05`。
9. **一次只换一个区**。转换器必须支持 `--only W05`；每区能独立进、能走完、能出，再做下一个。29 个区一起塞进去调试等于自找。
10. **不动 `game/combat_config.gd` 与 `game/mythic_*` 的数值/招表**。手感回归用旧的 M01 作对照基线。
11. **设计侧 0 错误基线必须保住**：改完不许让 `python tools/verify_map_specs.py` 报错。
12. **提交前必须跑通 §11 的三条命令**，输出贴进 PR 描述。

## 3. 运行时现状：引擎到底读哪些字段

### 3.1 旧文件长什么样

```json
{
  "version": 6,
  "regions": { "M01": { ... }, "M02": { ... } },   // 字典，不是数组；48 个
  "edges": [ { "a": "M01", "b": "M02", "kind": "main", "requires": "", "opener": "", "id": "main_01_02" } ]
}
```

- 旧 `kind` 取值：`main` 32 / `hidden` 8 / `local` 8 / `chapter` 7 / `return` 7。
- 旧 `requires` 只用**能力代号**（`P2`/`QS`/`PA`/`PW`/`PG`/`DS`/`DT`/`DB`）。
- 旧 `opener` = "由哪个区置位"（区号），配合 `local` 边使用。
- 每个 region 节点实测字段：`id / number / chapter / chapter_name / title / color / world_origin / bounds / rooms[] / links[] / interactions[] / structure{} / mythic{} / ability / layout_version`。
- **注意：旧结构里没有 `items` / `enemies` / `boss` 字段**——道具与灯龛都是 `interactions`，敌人不在数据里（`_spawn_patrol` 是硬编码巡逻）。

### 3.2 引擎实际读到的字段（这就是"必须提供"清单）

| 函数（`game/world_data.gd`） | 读什么 | 缺了会怎样 |

| `spawn(id)` | `rooms[0].rect` | 崩；且这是**出生点** |

## 4. 目标数据结构

### 4.1 顶层

```json
{
  "version": 7,
  "regions": { "W01": { ... }, "W26": { ... } },
  "edges": [ { "id": "E01", "a": "W01", "b": "W02", "kind": "main", "requires": "", "opener": "", "gate": "" } ]
}
```

- `version` 从 `6` 提到 **`7`**，与 `world_data.LAYOUT_VERSION` 对齐（它已自称 7，但旧文件写的是 6，属于既有不一致，本次一并修正）。
- `regions` 仍是**字典**（`world_data.db()` 用 `.regions[id]` 取值），不是数组。
- `id` 保持 `"W01"` 形式（`world_game` 里多处 `trim_prefix("M")` 需要一起改成 `trim_prefix("W")` —— 归到 §10 M5）。

### 4.2 Region 节点（逐字段）

| 字段 | 类型 | 必填 | 来源（设计 JSON） | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | ✓ | `id` | `"W01"` |
| `number` | int | ✓ | **本文件 §6 表** | 世界序 1—29，**不是 W 号**（W26 的 number 是 4） |
| `chapter` | int | ✓ | `chapter` | 1—8 |
| `chapter_name` | string | ✓ | 按章查表 | 见 §14.1 |
| `title` | string | ✓ | `name` | `TITLES` 靠它，HUD 直接显示 |
| `color` | string | ✓ | 按章查表 | 6 位 hex，**不带 `#`** |
| `world_origin` | `[x,y]` | ✓ | `canvas_origin` | 区左上角的世界坐标 |
| `bounds` | `[0,0,w,h]` | ✓ | `size` | **必须原点为 0**（§1 第 4 条） |
| `rooms` | Room[] | ✓ | `rooms` | 见 §4.3 |
| `links` | `[[i,j]]` | ✓ | `links` | **索引对**，见 §5 |
| `interactions` | Interaction[] | ✓ | `items` + `world_links` + `checkpoint` + `boss` | 见 §4.4 |
| `structure` | dict | ✓ | 派生 | 最小集见 §4.5 |
| `mythic` | dict | ✓（可为 `{}`） | — | 见 §4.6 |
| `ability` | string | ✓ | `""` | 新设计把能力门放在 `edges.requires`，这里**一律留空**（旧值 `VC` 会让 `db()` 改写，保持空最安全） |
| `layout_version` | int | ✓ | 固定 `7` | 决定走 `map_slice_geometry` |
| `items` / `enemies` / `boss` / `devices` | — | 选填 | 同名 | **引擎目前不读**，但必须原样带上，供 M3 接入时用（不带上等于丢数据） |

### 4.3 Room 节点

| 字段 | 类型 | 必填 | 来源 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | ✓ | `id` | 保持 `"R01"`（**区内唯一即可，不必加区前缀**；旧数据用 `M01_R01` 是历史包袱） |
| `name` | string | ✓ | `name` | 中文房名 |
| `rect` | `[x,y,w,h]` | ✓ | `rect` | 区局部，16 对齐，互不重叠 |
| `shape` | int | ✓ | `shape` | 中文枚举转 int，见 §5.2；**v7 几何不读它**，纯元数据 |
| `floor_y` | float | ✓ | `floor_y` | 地面 y（绝对坐标，不是相对 rect） |
| `ceiling_y` | float | 选填 | 派生 | 缺省 = `rect.y`。**层高 = `floor_y - ceiling_y`**，v7 几何用它生成自由空间 |
| `grid` | `[i,j]` | 选填 | — | 仅调试/编辑器用，可省 |
| `era` / `content` / `region` | — | 选填 | 同名 | 元数据，原样带 |

### 4.4 Interaction 节点

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | ✓ | **灯龛必须叫 `"rest"`**；跨区入口必须叫 `"travel_<对端区号>"`；其余自由（建议 `item_I01`、`boss_W05`） |
| `name` | string | ✓ | 显示名 |
| `at` | `[x,y]` | ✓ | **区局部绝对坐标**。`build()` 会把它吸附到最近落脚面，所以不必精确，但别差出半屏 |
| `room` | int | ✓ | 房间**索引**（不是房号字符串） |
| `radius` | float | ✓ | 普通交互 60；跨区入口写 `0` |
| `edge` | string | 跨区必填 | 该门对应的 edge id（`"E05"`） |
| `side` | int | 跨区必填 | `-1` 从左侧进 / `+1` 从右侧进；`entry()` 用它算落点偏移 |

> **`at` 是"贴墙的一点"，不是地面点。** 设计 JSON 的门位离房间地面 40—240 px（`E15` 的 W15 侧离地 168、`E16` 的 W15 侧离地 240）。跨区入口的触发区要做成 **从 `at.y` 到该房 `floor_y` 的整条门廊**（宽 96、`radius: 0`），落点一律吸附 `floor_y - 20`；把小方框摆在 `at` 上会"走到门口不触发"，按 `at.y` 直接落人会悬空。

### 4.5 `structure` 最小集（v7 路径只为这几个字段）

```json
"structure": {
  "connections": [ {"link": 0, "tier": "R1", "landings": 0, "return_assist": false} ],
  "hazards": [],
  "depth_cue": "",
  "skeleton": "spine"
}
```

生成规则（转换器必须照做）：

- `connections`：**每条 link 一条，`link` 等于索引**。水平连接（两端 `floor_y` 相同）随便填 `tier:"R1", landings:0`；**竖直连接必须按高差算**：
  - `dy = |floor_y(a) - floor_y(b)|`
  - `tier = "R1" if dy <= 320 else ("R2" if dy <= 640 else "R3")`
  - `landings = max(0, ceil((dy - 256) / 320))` ← 这是竖井里的落脚台数量，**少算会爬不上去**
  - `shaft_offset`：默认 `0`；若两房中心 x 差超过 `min(w_a, w_b)/2`，把 offset 调到让竖井落在两房重叠区间内
- `hazards`：本设计无运行时地刺，**一律 `[]`**（设计侧的 18 处地刺留在 `enemies[].tier=="环境"`，M3 再决定是否落成 hazard）。
- `depth_cue`：填 `""` 即可（旧值只是提示文案）。
- `skeleton`：自由文本，填 `"spine"`。

### 4.6 `mythic` 护栏（M0 必做，两行代码）

新设计没有"三灵因果锁"，`mythic` 一律写 `{}`。但现有引擎有两处会崩，必须先加护栏：

```gdscript
# game/world_data.gd  geometry() 内，替换
#   if region(id).mythic.has("chamber"):
var mythic: Dictionary = region(id).get("mythic", {})
if int(mythic.get("chamber", -1)) >= 0:
    result.append_array(load("res://game/mythic_environment.gd").fixtures(region(id), past, _flags))
```

```gdscript
# game/mythic_puzzle.gd  barriers() 内，第 17 行之后追加
if not zone.has("mythic"): return result
var _steps: Array = zone.mythic.get("steps", [])
if _steps.is_empty(): return result
```

**不要**给 29 个区硬塞假 `steps`：那会让 `progress()` 与 `attempt()` 行为错乱，后面更难拆。

### 4.7 Edge 节点（**新增一个 `gate` 字段**）

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `id` | string | `E01…E36` | 两侧 `travel_*` 交互的 `edge` 都指向它 |
| `a` / `b` | string | 设计 `a`/`b` | 区号 |
| `kind` | string | 设计 `kind` | `main` / `loop` / `secret` 三种，**保留原值**，引擎侧 `gate_reason()` 不再按旧 kind 分支 |
| `requires` | string | 设计 `requires` | **只放能力代号**（`P2`/`QS`/`PA`/`PW`/`PG`/`DS`/`DT`/`DB`），空串表示无 |
| `opener` | string | 派生 | 有进度旗标的边，填置位方区号；否则 `""` |
| `gate` | string | 设计 `requires` 里的**进度旗标** | `FINAL_DOOR` / `ENDGAME` / `w25_verdict_sealed` → 落到这里；能力代号不进 `gate` |

## 9. 转换器规格 `tools/build_runtime_world.py`

**签名**

```bash
python tools/build_runtime_world.py                # 全量：29 区 → game/data/world_regions.json
python tools/build_runtime_world.py --only W05     # 单区：只替换该 region 节点，其余保留原样
python tools/build_runtime_world.py --dry-run      # 只打印统计与差异，不落盘
```

**算法（8 步，顺序不能乱）**

1. 读 `data/world-25.json` → 得到 29 个 region 元信息 + 36 条边。
2. 按 §6 表算 `number`（世界序），按 §14.1 查 `chapter_name`，按 §14.2 查 `color`。
3. 逐区读 `data/wXX.json`：
   - 建 `房号 → 索引` 映射（**按 `rooms` 原顺序**）；
   - `links` 转索引对，同步生成 `structure.connections`（§4.5 公式）；
   - `world_links` → 两侧 `travel_*` 交互（`edge` 指向 edge id，`side` 按 side 字段取 `-1`/`+1`：`W`/`N` → `-1`，`E`/`S` → `+1`）；
   - `items` / `checkpoint` / `boss` → 交互；
   - 其余字段原样带。
4. 合并 `edges`：`requires` 按白名单分流到 `requires` / `gate`，`opener` 按"进度旗标边的置位方"填。
5. **自检**（不通过就退出，别落盘）：
   - 29 个 region、320 个 room、36 条 edge；
   - 每个 `links[i]` 的 `connections[i].link == i`；
   - 每条边的两侧 `travel_*` 都存在且 `edge` 一致；
   - 每个 `rooms[0]` 都是入口房（该区至少有一条 `travel_*` 交互落在 `room == 0`）；
   - `bounds == [0,0,size.x,size.y]`；
   - 门位两侧世界坐标完全相等。
6. 写 `game/data/world_regions.json`（`ensure_ascii=False`、`indent=2`、键序稳定 → 幂等：连跑两次文件字节一致）。
7. 打印统计表：区数 / 房数 / 边数 / 交互数 / 每章区数（应为 `5,3,4,3,4,3,3,3... ` 见 §14.3）。
8. `--only` 模式下只替换目标 region 节点与相关边，其余字节不动。

**硬要求**

- **幂等**：同输入两次输出必须逐字节相同（评审会查）。
- **不写设计目录**：转换器只读 `docs/design/maps/`，只写 `game/data/`。
- **不猜**：任何缺字段直接 `raise` 并指出 `区号 + 字段`，不许 `.get(default)` 蒙混。

## 15. 实施记录（2026-10-30，M0—M2 + 地图侧 M5 已落地）

本节记录**偏离上文**的地方，读完 §0—§14 后以此为最终事实。全部由 `tools/build_runtime_world.py` 与 `tests/test_world_29.gd` 固化。

**15.1 转换器追加的字段（§4.4 的补充）**

- `travel_*` 交互多了三项：`door`（`"h"` 横门 / `"v"` 竖门）、`porch`（门廊 `[x,y,w,h]`）、`landing`（落点 `[x,y]`）。
  门廊高度按 `max(96, floor_y - at.y)` 贴地生成，落点固定 `floor_y - 20`；竖门落点再偏出 ±96 以避开正下方的竖井口。
- `structure` 除 §4.5 四项外，还必须带 `pogo_halls: []`、`pogo_objects: []`、`tiers: []`、`niches: 0`——`world_game.load_map()` 与 `gate_reason()` 会无条件访问前两项。
- `boss` 空值写 `""`（不是 `null`），因为 §3.3 第 1、3 条的新判据是 `boss != ""`。
- `rooms[].shape` 设计侧实际有 8 种（`矩形/竖井/拱顶/梯形/斜坡/楼梯/L形/梯田`），映射为 0—7；未知值直接 raise。

**15.2 必须追加的引擎修正（§3.3 之外）**

| # | 位置 | 修正 |
| --- | --- | --- |
| 10 | `world_data.spawn()` | 出生点改用 `rooms[0].floor_y - 20`。**W01 R01 的 rect 底边是 960、地板在 576**，用 `rect.end.y` 会把人塞进岩体。 |
| 11 | `world_data.entry()` / `boundary()` | 优先读转换器写好的 `landing` / `porch`；旧公式（`at - side*40`、48×72 小方框）只作兜底。 |

| 14 | `map_slice_geometry.build()` | **重写**：房间是精确铺满的，`floor_y` 常常等于 rect 底边，而正下方就是另一个房间的自由空间——只按"非自由即实心"栅格化会让上下相邻房间合成一个空腔，全世界没有地板。现在额外生成 ①竖井/走廊开口 ②每房 `floor_y` 处 16px 实心楼板（开口处挖掉），并把轮廓按行/列合并成连续线段（最大区有 3 万开放格，逐格四边会拖垮帧率）。 |

| 16 | `mythic_environment.gd` | §4.6 只给了两处护栏，实际还有第三处：该节点每次 `load_map` 都会 `_ready()` 并读 `spec.chamber`。新增 `active` 标志，无 `chamber` 时整体空转。 |

**15.8 机关（devices[]）落地（2026-10-31）**

设计侧 58 个机关、7 种类型，字段是 `{id, room, type, levels, solution, flag, fail_feedback}`。实现分三层：

1. **数据层**：转换器为每个机关生成交互点。单档 → `device_<index>`；多盘口令（`"水轮 2 · 风轮 1 · 地脉 3"`）→ `device_<index>_<dial>`，三个盘各一个点、并按 72px 横向散开。`levels <= 1` 或 `solution` 是一整句说明（`"…坠入即落到燃羽堆最上层 y=2144"`）的机关**不拆盘**，只留一个说明牌交互——这类共 3 个，属"无解谜"。
2. **规则层**（`world_data.gd`）：`device_targets()` 判定目标档位（空数组 = 无解谜），`device_pads()` 给出"解谜类机关置位后补的落脚台"。目标档 0 的机关（如 `w12_dev_lift`）开场即就绪，旗标静默置位，否则永远等不到一次"调对"。
3. **运行时**（`game/map_devices.gd`）：
   - 档位状态 `state[]` 按盘独立循环，全部对上才置 `flag` 并给 30 魂魄；档位写进 `chapter_flags["dev_<map>_<index>"]`，重进区不重置。
   - `升降平台`（22 个）是唯一实体类型：`AnimatableBody2D` 160×12，逐帧限速 110px/s 升降，并**手动带人**（`AnimatableBody` 不载人）。每档 96px。
   - 其余 6 类置位后由 `_device_pads()` 在机关房 `floor_y - 160` 补一块落脚台——物理后果统一走几何，不为光路 / 潮位 / 风场 / 音柱 / 根系 / 三灵各写一套特判（各类型的具体演出留 M4）。

注意：`operate()` 会打开日志面板，面板 `get_tree().paused = true`，所以**升降台要等面板关掉才开始动**——这是暂停机制的正常表现，测试里必须先 `journal.close_reader()`。

验收：`WORLD29 ... CHECKS=1475 FAILURES=0`，新增 80 项覆盖"逐区交互点数量 / 初始旗标未置位 / 全部档位可调到目标 / 置位生效 / 升降台真的升起 8px→高度增长 >60px"。
